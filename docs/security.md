# Security baseline

LessonCue is local-network software, not trusted-network software. Treat every request as untrusted.

Linux installers and automatic updates verify the Ed25519 signature on the complete release manifest with a pinned public key before trusting a checksum or executing downloaded code. Tagged builds also carry GitHub/Sigstore provenance and SBOM attestations, and CI scans tracked source plus the exact container for high/critical vulnerabilities, insecure configuration, and secrets. Signing operations run only in the `v*`-restricted, maintainer-reviewed `production-release` environment. See [release-signing.md](release-signing.md) for the trust fingerprint, manual verification, key storage, rotation, and compromise recovery.

- Keep the server off the public internet. Use a supported VPN for remote planning.
- Leave the rotating pairing secret enabled unless an operator explicitly needs a fixed installation PIN, and protect service logs.
- Use HTTPS with a trusted local certificate where device management permits it. The supported Caddy workflow, Android connection policy, and trust instructions are documented in [local-network-security.md](local-network-security.md).
- Give each TV an independent revocable credential.
- Store PINs, passwords, and device tokens only as adaptive or cryptographic hashes on the server.
- Validate file signatures as well as extensions before media processing.
- LessonCue validates container magic and Office/PDF package structure independently of file names and browser MIME claims before processing. On native Linux, FFmpeg, FFprobe, LibreOffice, and Poppler run through a root-installed Bubblewrap worker with read-only media, explicit write roots, an isolated PID/filesystem/device environment, no network, bounded logs, and CPU/memory/file/process/time limits. Only the separate yt-dlp job receives network access, still under the remaining limits and strict YouTube-only URL checks. Windows runs as LocalService, assigns converter trees to memory/process/CPU-time-limited Job Objects, uses application/data ACLs, and gives untrusted FFmpeg/FFprobe a private outbound-blocked executable copy; installed document converters receive matching outbound firewall rules.
- Do not fetch arbitrary external URLs. The optional YouTube importer is a narrow exception: accept exact YouTube hostnames only, pass fixed arguments directly to the bundled downloader without a shell, disable downloader configuration and playlists, and enforce the local storage allocation. Resolve and block loopback, private, link-local, and metadata addresses for any future fetch feature unless an administrator explicitly allowlists a local stream.
- LessonCue uses role-based browser sessions, optional replay-resistant TOTP MFA for Service Admins, same-origin mutation checks, CSP, rate-limited pairing/login/account setup and expensive processing, revocable hashed device credentials, forced replacement of administrator-issued temporary passwords, and durable local data-protection keys. Temporary browser display pairings expire after two hours without a heartbeat; administrator-designated permanent browser screens and native TV credentials remain until revoked. Uploaded media URLs remain reachable on the trusted television network so native players can stream them; do not expose the service directly to the internet.
- Upload creation and completion are separately rate limited, active sessions are bounded per account, and the full declared byte length is reserved atomically before any chunk is accepted. Sessions and chunk maps are owner-bound in SQLite, abandoned partials expire after 24 hours, completion hashes while streaming, and magic/package validation rejects mislabeled or unsafe content before processing. Service Admins may apply stricter file, daily account/role/class, and verified-codec policies.
- Retain audit logs and test backups and restoration.
- Browser-created backups are password-encrypted `.lcbak` files. Keep the password outside the archive, verify downloaded copies from **Settings → Privacy & backups**, and leave server credentials/data-protection keys excluded unless a documented migration requires them.
- Scheduled-backup and Nextcloud/ownCloud/WebDAV credentials are locally protected and the policy file is excluded from all exports. Remote pruning is restricted to direct-child `lessoncue-*.lcbak` files after a verified upload; unrelated provider files are not deleted. Treat the LessonCue server as able to run the configured policy, keep the human-readable backup password elsewhere, and test a downloaded off-server copy on a spare server.
- Direct migration grants contain 256 random bits, expire after 30 minutes, and work once. Share the token and backup password through separate channels when practical; the source sees only the bearer token and encrypted archive, never the password.
- Keep SSH or equivalent physical administrator access available for account recovery. The recovery command runs as the restricted `lessoncue` account, stores only a new adaptive password hash, disables MFA for the recovered account, audits the reset, and invalidates existing sessions for that account.
- Service Admins and App Admins can edit local names, usernames, emails, roles, and passwords from **Users**. They can also pause, reactivate, and permanently delete accounts below their authority. Only Service Admins can create, modify, pause, or delete another Service Admin. Pausing or changing an account invalidates its previous browser sessions immediately.
- Native Linux port and `.local` name changes use typed files watched by a root-owned helper; the web process receives no sudo access. The service has only the bind capability needed for port 80, and an unhealthy port change rolls back to the last working listener.
- LessonCue prevents an administrator from pausing or deleting the account they are currently using, rejects duplicate usernames, and always preserves at least one active Service Admin. Use the SSH recovery procedure if every known Service Admin password is lost.

Report security issues privately to the repository owner rather than opening an issue containing exploit details.
